# GPU Trace Analyzer - Project Overview

## What This Project Does

This project is a **CUDA-accelerated MPI trace analyzer** that reads OTF2 trace files generated by Score-P-instrumented MPI programs, and computes 8 wait-state metrics that identify performance bottlenecks in MPI communication patterns. These are the same metrics produced by the industry-standard tool **Scalasca** and by the CPU-based reference implementation **TileTrace**.

The key idea: replace TileTrace's multi-node CPU-based parallel analysis with a single-GPU approach that uses CUDA kernels for parallel event processing, while using MPI only for accelerating I/O (parallel trace reading).

## The 8 Wait-State Analyses

| # | Analysis | What It Measures | Applies To |
|---|----------|------------------|------------|
| 1 | **Late Sender** | Sender started MPI_Send after receiver started waiting (MPI_Recv/MPI_Wait) | Point-to-point |
| 2 | **Late Receiver** | Receiver started waiting after sender started MPI_Send | Point-to-point |
| 3 | **Barrier Wait** | Time each process waited for the slowest to arrive at MPI_Barrier | Barrier collectives |
| 4 | **Barrier Completion** | Time imbalance in how processes exit MPI_Barrier | Barrier collectives |
| 5 | **Early Reduce** | Root arrived early relative to slowest member in Reduce/Gather | Root-based collectives |
| 6 | **Late Broadcast** | Root arrived late relative to early-arriving members in Bcast/Scatter | Root-based collectives |
| 7 | **Wait NxN** | Same as barrier wait but for AllReduce, AlltoAll, AllGather, etc. | N-to-N collectives |
| 8 | **NxN Completion** | Same as barrier completion but for N-to-N collectives | N-to-N collectives |

## Processing Pipeline

```
                          +-----------------------+
                          |  OTF2 Trace File      |
                          |  (.otf2 + traces/)    |
                          +-----------+-----------+
                                      |
                    Step 1: MPI-Parallel Two-Pass Reading (split-phase API)
                    readOTF2TracePhase1() → event count + opaque handle
                                      |
            +-------------------------+-------------------------+
            |                         |                         |
   Step 2: Shared Memory Window   readerFillSoA()    (or local alloc for single-rank)
   MPI_Win_allocate_shared        → fill SoA into SHM
            |                         |
   Step 3: P2P Matching (CPU, local)  Step 4: Collective Grouping (CPU, local)
   timestamp-sorted FIFO queues       comm_set-based, produces CSR
            |                         |
   Step 3.5: Timestamp Correction (optional, --time-correct)
   CLC blocking-only neutralization
            |
            +-------------------------+
                                      |
                    Step 5: Adaptive Batch Streaming (single GPU, rank 0)
                    GPUMemoryPool pre-allocated, CUDA stream
                    K = min(P, VRAM_budget / per_rank_data)
                    For each batch of K ranks:
                      - Remap match_partner, build batch CSR
                      - H2D (pinned DMA) → 5 CUDA Kernels → D2H
                      - Accumulate results
                    Memory: O(K*N/P), not O(N)
                                      |
                          +-----------v-----------+
                          | CPU Statistics        |
                          | (nth_element, O(n))   |
                          +-----------+-----------+
                                      |
                          +-----------v-----------+
                          |   Formatted Output    |
                          |   (stdout)            |
                          +-----------------------+
```

## Key Design Decisions Summary

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Data layout | **SoA** (Structure of Arrays) | GPU coalesced memory access; warps read contiguous addresses |
| Trace reading | **MPI-parallel two-pass**, split-phase API | Dominated by I/O; parallelizing across ranks gives near-linear speedup; split-phase enables direct-to-SHM writing |
| P2P matching | **CPU** (pure `.cpp`), timestamp-sorted FIFO per rank | Requires temporal ordering; done locally on each rank in parallel; `.cu` caused 4.5x overhead from CUDA runtime init |
| Collective grouping | **CPU**, comm_set-based CSR per rank | Variable-length groups; small fraction of total events; produces GPU-friendly CSR |
| Data sharing | **MPI shared memory window** (same-node primary) | Zero-copy: all ranks write into shared buffer; eliminates 16+ GB MPI Send/Recv; 50% memory savings vs double-buffer |
| GPU analysis | **Adaptive batch streaming on rank 0** | K ranks' data per GPU batch; K computed from VRAM; O(K*N/P) memory; GPUMemoryPool eliminates per-batch alloc |
| Analysis kernels | **GPU CUDA kernels** | Massively parallel event processing; one thread/event for P2P, one block/group for collectives |
| Event linking | **Index-based** (int32_t) | GPU-compatible; no pointers across host/device |
| Statistics | **`std::nth_element`** (O(n) average) | 4-5x faster than `std::sort` for quartile computation |
| Timestamp correction | **Blocking-only CLC neutralization** | Only neutralizes blocking MPI_Recv violations; non-blocking MPI_Irecv left unchanged (genuine late_receiver) |

## Comparison with TileTrace

| Aspect | TileTrace (CPU) | GPU Analyzer |
|--------|-----------------|--------------|
| Parallelism | MPI across nodes | MPI for I/O + CPU matching, single CUDA GPU for analysis |
| Data Layout | AoS (struct Event) | SoA (12 contiguous arrays) |
| P2P Matching | CPU hash map during replay | CPU timestamp-sorted FIFO queues |
| Collective Groups | Inline with matching | Separate CPU preprocessing -> CSR |
| Reading | Serial or MPI (1-pass per rank) | MPI-parallel two-pass (contiguous location blocks) |
| Hardware | 2x Xeon Gold 6530, 1TB RAM | 1x RTX 4090/5090 + any CPU |

## Validation Status

All 8 analyses **match Scalasca exactly** (count and sum within 1 picosecond of floating point rounding):
- late_sender, late_receiver, barrier_wait, barrier_completion, early_reduce, late_broadcast, wait_nxn, nxn_completion

Validated on CG Class B and CG Class C traces (64 locations). See [09-TESTING.md](./09-TESTING.md) for detailed results.
