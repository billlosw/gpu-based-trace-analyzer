# GPU Trace Analyzer

CUDA-accelerated MPI trace analyzer for OTF2 traces generated by
Score-P-instrumented MPI programs. The analyzer reads trace events into a
Structure-of-Arrays layout, matches communication events, groups collectives,
runs wait-state analysis kernels on a single GPU, and prints Scalasca-style
summary statistics.

## Requirements

| Dependency | Recommended version | Notes |
|---|---:|---|
| CUDA Toolkit | 12.8.x | Toolkit version must not exceed the installed NVIDIA driver support |
| CMake | 3.24+ | Required for CUDA language support |
| MPI | Open MPI 4.x or compatible | Multi-rank reading requires MPI |
| OTF2 | 3.0.3 | Used to read OTF2 traces |
| NVIDIA GPU | Compute capability 8.9+ | The build targets Ada-class GPUs by default |

If CUDA is not auto-detected by CMake, pass the CUDA compiler explicitly with
`-DCMAKE_CUDA_COMPILER=/path/to/nvcc`.

with spack:
```
spack load cuda@12.8.0 cmake openmpi otf2@3.0.3
// spack load scorep scalasca dyninst
```

## Build

```bash
cd gpu-analyzer
mkdir -p build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
make -j8
```

Useful configuration options:

```bash
# Build with Scalasca timestamp semantics; this is the default documented mode.
cmake .. -DCMAKE_BUILD_TYPE=Release -DTIMESTAMP_MODE=SCALASCA

# Build with an explicit CUDA compiler.
cmake .. -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CUDA_COMPILER=/path/to/nvcc
```

The main executable is written to:

```text
build/gpu_analyzer
```

## Run

Basic single-process run:

```bash
./build/gpu_analyzer /path/to/trace/traces.otf2
```

Recommended MPI run for parallel trace reading:

```bash
srun --mpi=pmix -n 64 --gres=gpu:1 \
  ./build/gpu_analyzer /path/to/trace/traces.otf2
```

`--mpi=pmix` is important for Open MPI builds that use PMIx. Without it, SLURM
may start the job with an incompatible PMI mode and MPI initialization can fail.

Command-line syntax:

```text
gpu_analyzer <path/to/traces.otf2> [--time-correct] [--gpu-matching]
```

Options:

| Option | Effect |
|---|---|
| `--time-correct` | Enables blocking-receive timestamp neutralization for clock violations |
| `--gpu-matching` | Enables GPU sort-based P2P matching and GPU segment-scan collective grouping where available |

Only rank 0 performs GPU analysis. The `-n` value controls how many MPI ranks
participate in trace reading and host-side preprocessing.

## SoA Cache

After an OTF2 read, each MPI rank may write a binary SoA cache next to the trace:

```text
<trace_dir>/soa_cache/soa_cache_r<rank>_n<nprocs>.bin
```

The cache stores the final per-rank SoA arrays and communicator metadata. On
later runs with the same trace fingerprint and same MPI rank count, the reader
loads this binary data directly and bypasses OTF2 callback replay.



## Current Pipeline

```
OTF2 trace anchor (.otf2)
  -> MPI-parallel two-pass OTF2 reading
  -> optional per-rank SoA binary cache
  -> TraceDataSoA storage
  -> P2P send/recv matching
  -> collective grouping into CSR
  -> optional timestamp correction (--time-correct)
  -> adaptive batched GPU analysis on rank 0
  -> CPU statistics
  -> stdout report
```

The multi-rank path uses MPI for parallel trace reading. On a same-node run,
ranks write into a shared-memory window and rank 0 streams batches to the GPU.
If ranks span multiple nodes, the program falls back to an MPI gather path.

## Analyses

The executable reports eight wait-state metrics:

| Metric | Applies to | Meaning |
|---|---|---|
| `late_sender` | Point-to-point | Sender entered send after receiver was already waiting |
| `late_receiver` | Point-to-point | Receiver posted the receive after sender entered send while send was still blocked |
| `barrier_wait` | Barrier collectives | Member wait time until the slowest barrier entrant arrives |
| `barrier_completion` | Barrier collectives | Exit-time imbalance relative to the fastest barrier completion |
| `early_reduce` | Rooted reduce/gather collectives | Root wait caused by later-arriving members |
| `late_broadcast` | Rooted broadcast/scatter collectives | Member wait caused by late root arrival |
| `wait_nxn` | N-to-N collectives | Barrier-style wait time for all-to-all/all-reduce style operations |
| `nxn_completion` | N-to-N collectives | Completion imbalance for N-to-N collectives |

Internally, timestamps are stored in picoseconds. Printed statistics are scaled
to seconds.


## Architecture

Important modules:

| Path | Responsibility |
|---|---|
| `src/main.cu` | MPI setup, pipeline orchestration, batching, result printing |
| `src/reader/OTF2SoAReader.cpp` | Distributed two-pass OTF2 reader and split-phase fill API |
| `src/reader/SoACache.cpp` | Per-rank binary SoA cache read/write |
| `src/matching/P2PMatching.cpp` | CPU timestamp-sorted FIFO P2P matching |
| `src/matching/CollectiveGrouping.cpp` | CPU collective grouping into CSR |
| `src/analysis/TimestampCorrection.cpp` | Optional blocking-only timestamp correction |
| `src/analysis/AnalysisKernels.cu` | CUDA kernels, GPU memory pool, async analysis path |
| `src/analysis/Statistics.cpp` | Count, sum, mean, variance, min/max, and quartiles |

Core data structures:

| Type | Purpose |
|---|---|
| `TraceDataSoA` | Event arrays in GPU-friendly SoA layout |
| `CollectiveGroupCSR` | CSR representation of collective groups |
| `RawAnalysisOutput` | Per-metric raw duration vectors from kernels |
| `AnalysisResult` | Final summary statistics per metric |
| `GPUMemoryPool` | Reusable device memory for batched analysis |

## Notes

- The default P2P matching path is CPU-based because timestamp ordering is part
  of correctness. `--gpu-matching` enables the newer GPU preprocessing paths for
  performance comparison and large traces.
- The same-node MPI path avoids large MPI transfers by using shared memory and
  letting rank 0 stream batches directly to the GPU.
- The GPU kernels are intentionally simple: one thread per event for P2P
  analyses and one block per collective group for collective analyses.
- Large traces are processed in adaptive batches sized by available GPU memory.
